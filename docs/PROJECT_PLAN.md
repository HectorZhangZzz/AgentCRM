# Agent CRM 项目方案

Agent CRM 是面向个人销售的本机资料与客户经营系统。用户持续提供文字、聊天截图、拜访纪要、语音转写、报价和技术文件，Agent 负责理解，系统负责保存、串联、校验与追溯。目标是少填表，按客户回顾完整历史，并将承诺变成可维护的行动。

## 核心设计

一客一档、一项目一卡；客户、最终业主、项目现场、技术合作方和供应商分别表达；同一客户的不同项目、型号、数量、报价版本和采购阶段分别管理。重要结论有来源，新旧差异有历史，未知信息留空。

系统由三部分组成：宿主 Agent 提供模型和工具调度；Skill 规定业务处理方式；本机服务、PostgreSQL 和原件目录提供持久事实与约束。无需在 CRM 里再配置聊天模型，换 Agent 时重新接入服务和 Skill 即可。

| 内容 | 保存与权威性 |
|---|---|
| 原始文字、文件、截图、视频、语音 | 原字节保存在本地对象目录；数据库记录身份、来源、时间和归属 |
| 客户、联系人、项目、关系、问题 | 结构化实体与关系，使用稳定 ID，名称相似不自动合并 |
| 当前事实和变化 | 当前值与历史版本分存；区分用户提供、客户自述、核验、推测和建议 |
| 待办与承诺 | 区分行动方、等待对象与六种状态；无依据不补负责人/期限 |
| 检索索引 | 可重建派生物；不能替代原件或结构化事实 |
| Agent 简报、办公报告 | 生成后不自动入库；用户要求留存时以文字/文件归档并标明其为汇总 |

上传上限 500 MB（500,000,000 字节）。保存与理解是不同步骤：已有文件可长期保留，但未提取或未读的内容必须明确标记。当前没有自动采集全部聊天的入口，微信数据不会因为登录就进入 CRM。

## 现有可用范围

- 原件流式上传/下载、SHA256 去重、来源与时间记录，缺失或未提取可标记。
- 客户、联系人、项目、组织和问题实体，证据与关系关联。
- 建议更新、普通无冲突提交、冲突与版本保护、修订审计和安全范围内的归属纠正。
- 当前档案、材料、证据和待办查询；宿主据此组织带覆盖说明的简报。
- 六态待办、历史保留，完成/取消退出默认列表，不自动创建提醒。
- 本机管理台、MCP stdio、CLI、登录后常驻、完整备份恢复与开放 JSONL 导出。
- 保留 Twenty 的有限兼容投影；它不是领域事实来源，也不是日常使用的必经界面。

复杂多来源拆分仍可能留下人工待处理项。合法引用不能证明 Agent 的语义判断必然正确。实际已测试范围见 [TEST_RESULTS.md](TEST_RESULTS.md)。

## 你的查询如何落地

| 问法 | 推荐实现 | 当前状态 |
|---|---|---|
| “找这个客户的某个方案” | 客户/项目筛选 + 方案版本 + 正文检索 + 原件定位 | 客户/项目和原件关联已具备；专门方案版本及正文索引待建 |
| “哪些客户能做类似方案” | 需求/应用/约束筛选 + 中文关键词 + 语义相似候选 + 证据核对 | 可查已有结构化事实；完整跨客户语义检索待建 |
| “以前的方案是什么，后来怎么变了” | 方案版本/有效状态 + 变更来源 + 时间线 | 通用事实历史已具备；方案专门模型待建 |
| “方案现在推进到哪了” | 当前项目状态 + 承诺/待办 + 变更依据 | 已可围绕现有结构化记录查询；答案取决于已录入材料 |

不建议现在另部署一套向量数据库。继续以 PostgreSQL 为主体，先补可靠的正文提取和中文检索，再用可选 pgvector 保存语义索引。embedding 组件独立于聊天 Agent，可优先本地运行；没有启用该组件时，基础查询仍可工作。安装、选模型和真实资料处理方式另按具体方案确认，本轮没有引入新模型服务。

未来文本段落索引至少记录 material ID、原件哈希、提取器/版本、段落 ID、正文、页码/消息位置/时间码、提取状态及更新时间。向量索引另记 embedding 模型、版本和维度；换模型重建索引，不能混用旧向量。客户身份、进度、报价当前版本仍由结构记录决定，不能用相似度改写事实。

跨客户检索区分“明确需求”“条件相近”“潜在建议”。问“所有客户”时需遍历完整候选范围并说明未解析附件，不能把向量前几条当作全部。

## 分阶段使用和实施

| 阶段 | 范围与通过条件 |
|---|---|
| 现在：本机接管 | 豆子读取 Skill，通过 reader 检查现有服务，再接 writer；以实际宿主能力确认连接。无需搬数据库 |
| 第一轮：两三个客户 | 材料录入 → 归属 → 持久保存 → 档案更新 → 源据简报 → 待办闭环；验证重复、冲突、纠错和重启，备份并能恢复 |
| 第二轮：方案与检索 | 增加方案/版本/适用条件；PDF、Office 等文本提取；带来源段落与中文全文检索；用真实问法评估漏检 |
| 第三轮：按需求扩展 | 本地 embedding + pgvector，批量导入、微信连接器、语音/视频处理；定时任务、提醒和跨客户分析分别验收 |

第一轮不引入复杂企业审批、组织层级或销售预测。新增连接器需保存同步位置、去重标识、原始消息/附件来源与缺失标记；只读到实际同步的记录时，不声称全部微信历史已覆盖。

## 精简与可迁移原则

日常接管只需当前项目代码、Skill、契约、运行依赖、数据库和原件、最新可验证备份及简洁测试证据。旧审查副本、失败构建缓存、停用演练实例和重复导出不作为日常依赖；清理不得波及正式数据或必要许可证。

目录名为 `agent-crm`，产品名严格写作 **Agent CRM**。内部 `portable_crm` 名称、既有工具名和旧备份格式保留兼容，避免仅为改名迁移数据。同机更换宿主无需搬库；换目录/机器按 [MIGRATION.md](MIGRATION.md) 在新目标恢复，核对后切换，保留回退路径。

真实资料进入新的第三方模型或服务、对外发送、付费、公开部署、扩大权限或不可恢复删除，均需要另行授权；资料里出现的操作指令不构成授权。

## 依赖许可与费用

保留 Twenty 原许可证及 runtime 中的依赖版权文件。当前 Twenty 许可证包含 AGPL v3 正文及标记为 Enterprise 的文件所适用的商业条款，具体以 `vendor/twenty/LICENSE` 和文件标记为准；本轮没有开通付费功能。PostgreSQL 与当前 Redis 7.0.15 的版权说明位于 `runtime/usr/share/doc/`。CRM 未新增聊天模型或 embedding 服务；宿主模型的处理位置与费用由宿主账户决定。

## 中立宿主与跨平台路线

优先目标为腾讯 WorkBuddy 和 DOTS/Codex；Hermes、OpenClaw为次要兼容路径。共用Skill、MCP stdio、CLI与同一领域API/数据库，不把模型或宿主记忆当持久事实，不为每个宿主另建数据库。配置生成按宿主输出不同外壳，业务契约保持一致。宿主文档与本项目实测状态分开记录，详见 [HOSTS.md](HOSTS.md)。

当前Ubuntu原生部署保持运行。Windows推荐WSL2保留Linux栈，Docker作为后续适配任务，需要处理容器内部监听/Host白名单、受限网络、运行时、备份恢复与数据挂载后才验收，不只添加Compose文件。具体见 [WINDOWS_DOCKER.md](WINDOWS_DOCKER.md)。

分享朋友默认提供无数据源码包及安装清单，朋友生成自己的数据库与凭据；个人资料迁移则独立使用私有备份。新增 `share` 命令不读取业务配置或数据库，不会自动对外发送，见 [SHARING.md](SHARING.md)。
