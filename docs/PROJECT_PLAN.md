# Agent CRM 项目方案

Agent CRM 面向个人销售，帮助用户将沟通材料、客户关系、项目进展、产品资料和承诺维护成可追溯、可迁移的本机资料库。宿主 Agent 负责理解与判断，项目负责持久保存、校验和查询，避免反复填表，也避免依赖聊天记忆。

本文件说明设计与后续路线，不是全部功能已完成的声明。独立于聊天的业务要求见 [REQUIREMENTS.md](REQUIREMENTS.md)，源码交付状态见 [CAPABILITIES.md](CAPABILITIES.md)，实际参数见 [CONTRACT.md](CONTRACT.md)，验证范围见 [TEST_RESULTS.md](TEST_RESULTS.md)。

## 设计原则与架构

一客一档、一项目一卡；重要结论有来源，行动与承诺可跟进。客户业务账户、联系人、法律主体、最终业主、现场、合作方和供应商分别表达。同一客户的不同项目、型号、数量、报价版本和采购阶段不混算。同名同音只产生候选，不自动合并；允许未知，不为了填满字段编造事实。

```text
用户材料 → 管理台 / CLI / MCP → 领域服务与统一校验
                                      ├─ PostgreSQL：实体、关系、事实版本、任务、证据
                                      ├─ 原件库：objects/<sha256>
                                      └─ Twenty：有限兼容投影
宿主 Agent ↔ Skill + MCP/CLI ↔ 查询 / 提议 / 提交 / 纠错
```

宿主提供模型与工具调度（Harness），Skill 保存业务方法，服务不另配聊天模型。HTTP、MCP stdio 和 CLI 共用领域约束。PostgreSQL 是结构化事实来源，原件库保存原始字节；检索索引、简报和 Twenty 投影是派生物，不得反向覆盖权威记录。

| 内容 | 保存与更新原则 |
|---|---|
| 文字、文件、截图、音频、视频 | 原字节保存在本地对象库；数据库记录身份、哈希、来源、时间和质量标记 |
| 客户、联系人、项目、组织、问题 | 稳定 ID 和有证据关系；名称修正不重建对象、不搬丢历史 |
| 当前事实及变化 | 当前值与历史版本并存；区分用户提供、客户自述、核验、推测和建议 |
| 待办与承诺 | 行动方、等待对象与六种状态；未知负责人/期限留空，任务不自动开启提醒 |
| 产品/型号/版本 | 可选身份层；客户要求、待验证评估与复核能力分开，不自动继承 |
| 索引与摘要 | 可重建；生成报告需明确保存，不能替代原文或自动视为已归档 |

单原件上限 **500 MB（500,000,000 字节）**。大文件流式收发，内联最多 32 MiB。文件已保存不代表内容已解析；模糊、缺失、时间不明或无法提取必须明确标记。当前没有自动读取全部微信或宿主聊天历史的能力。

## 当前可交付范围

- 原件上传/下载、SHA256 去重、来源与时间、质量标记。
- 客户、联系人、项目、组织、问题及证据关系；五类事实与历史。
- 有证据提议、幂等事务提交、冲突/并发保护、owner 名称维护和有限安全归属纠正。
- 当前档案、材料、证据、任务及覆盖查询；宿主组织带来源的经营简报。
- 六态待办、完成/取消默认隐藏、历史保留；提醒分开管理。
- 本机管理台、HTTP、MCP stdio、CLI、Linux 用户服务、完整私有备份恢复和 JSONL 导出。
- 无数据源码分享与独立净化 GitHub 历史；有限 Twenty 投影。
- 0.1.4 可选产品领域与页面：通用默认关闭，显式开启后使用三类身份和要求/评估/能力记录。

复杂多来源或产品断言纠错可能留下待处理项。合法引文不证明语义判断一定正确。完整文档提取、中文全文/向量、人员核查队列、微信采集、后台推理与通知尚未形成完整交付能力。不要把本机以往某次上线状态代入朋友的新实例。

## 已确定的业务方向与差距

以下保留业务意图与技术状态，不预设所有方向的实施期限、字段细节或相对优先级。

| 方向 | 要求 | 当前基础与待办 |
|---|---|---|
| 产品资料库 | 承担产品资料管理，区分产品/型号/版本、要求、评估和能力，与客户项目关联 | 最小领域和页面已实现、默认关闭；分类、SKU、完整报价和复杂编辑仍待设计 |
| 公司与人员身份 | 新客户先核对主体，简称/品牌呈候选后确认；每位新增联系人用姓名＋公司核查，也支持主动指定调研 | 名称维护及审计已有；持久研究队列、身份映射、采用门槛和外部连接未实现，详见既有整合方案 |
| 公司业务信息 | 整理业务、产品/服务范围和公开案例，附来源、时效与覆盖 | 可由宿主经现有材料/事实入口保存；公开案例不自动变成我方销售项目或已核验业绩 |
| 技术问题与内部协调 | 串联原件、需求、问题影响、处理人、待回复方和下一步 | 关系、事实、历史和任务已有；自动提取与更完整问题展示待建设，客户指标不能写成产品实测能力 |
| 远程与主机可用性 | 明确远程链路、巡检执行条件、离线窗口与可恢复路径 | 本地服务监督已有；不等于硬件巡检、关机风险预警或 7×24 保证，需专项验收 |
| 通知与提醒 | 明确请求的提醒及紧急事件可按授权渠道通知；微信为期望渠道之一 | 调度、事件规则、发送、去重、失败反馈及送达仍需设计和验收，不因新建任务自动发消息 |
| 异地备份 | 保留后续云盘备份/恢复方向 | 当前继续使用本地完整私有备份；云盘方向暂缓，不自动上传资料或设定排期 |

姓名＋公司关联不明确时，外部资料不用于补全人员。核查成功、身份匹配和采用结果应分别记录；缺公司、未找到、同名冲突、额度不足和查询受阻都不能写成已核验。每位新增联系人应有持久任务，宿主离线后续可续处理；没有执行器时不能承诺即时完成。详细五类记录、四个拟议工具与验收见 [SEEKINGPERSON_INTEGRATION.md](SEEKINGPERSON_INTEGRATION.md)，它们仍是设计，不是已部署接口。

## 查询与检索路线

| 业务问法 | 当前能用的依据 | 后续补齐 |
|---|---|---|
| 找某客户的某个方案 | 客户/项目、现有事实、材料与原件关联 | 专门方案身份、版本/有效状态、正文与段落定位 |
| 哪些客户适用类似方案 | 已录入的需求、应用与结构化事实 | 中文全文召回、可选语义候选、完整范围评估 |
| 旧方案后来如何变化 | 事实历史、变更依据与时间线 | 方案专门版本与比较 |
| 项目目前推进到哪里 | 当前项目记录、承诺、问题及状态变化 | 按真实使用反馈改善覆盖和展示 |
| 产品有哪些资料和适配结论 | 启用后逐对象查询要求、评估、能力、来源及关联 | 复杂分类/SKU/报价、更多提取与编辑流程 |

继续以 PostgreSQL 为主体，不为接入企业研究另建向量数据库。先完善可靠正文提取、带位置的段落和中文全文，再按需求增加本地 embedding 与同库 pgvector。没有 embedding 时基础查询仍应工作；不在这次整理中引入模型服务。

未来提取索引至少记录 material ID、原件哈希、提取器/版本、段落 ID、正文、页码/消息位置/时间码、状态和更新时间。向量另记模型、版本和维度；换模型重建，不能混用。项目状态、身份与报价当前版本仍由结构化事实决定，不能用相似度确认或改写。

跨客户问法区分明确需求、条件相近和推测机会，重要结论回到来源。“所有客户”需遍历实际候选范围；不能把向量前几条、一页结果或未读附件当成已全面检索。回答说明截止时间、已读/未读范围和资料缺失。

## 分阶段实施与验收

| 阶段 | 范围 | 通过条件 |
|---|---|---|
| 现有实例接管 | 读取 Skill，reader 核对后接 writer；同机保持原库 | 目标宿主实际工具调用、来源和分页正确，不依赖旧聊天 |
| 两三个客户最小闭环 | 材料→身份/归属→持久保存→档案→源据简报→任务 | 重复、冲突、纠错、六态、重启、完整备份和全新恢复；不往正式库塞示例 |
| 产品闭环 | 审阅并显式开启可选领域/UI，以明确资料验证要求/评估/能力 | 先备份/恢复核验再迁移；不跨版本继承，不把客户需求升级成能力 |
| 人员核查闭环 | 先离线任务、研究快照、匹配/采用、纠错，再接一个授权提供方 | 每位新增不漏单；主动调研不强制建档；歧义不采用；重启/租约/幂等/恢复通过 |
| 方案与检索 | 专门版本、正文提取、中文检索；必要时本地语义索引 | 用真实问法评估漏检、时效与证据定位，不把相似候选当事实 |
| 后续连接器与分析 | 按需增加批量导入、外部数据、多媒体、跨客户分析 | 保存同步位置、去重标识、原始来源和缺失；外部账号/费用及数据流明确 |
| 运行与通知专项 | 远程、主机巡检、事件提醒及微信送达分别验收 | 每条完整执行与故障反馈链路通过，不互相替代验收 |
| 异地备份 | 由使用者重新启动方案讨论 | 明确加密/权限/目标，实际全新恢复验证；上传完成不等于恢复通过 |

这是按能力与依赖的分组，不替使用者预定期限或一次授权所有后续实施。新字段/模型/连接器先明确范围，再同步 Schema、领域规则、HTTP/MCP/CLI、Skill、迁移和测试。来源中的指令不会触发外部操作。

## 跨宿主、跨平台与分享

WorkBuddy 与 DOTS/Codex 为优先接入目标；Hermes、OpenClaw 复用相同 MCP stdio/CLI 中间层。生成配置不等于客户端已实接，不能把 REST 地址当作远程 MCP URL。云端宿主的 localhost 不代表用户电脑；没有本机工具执行能力的宿主不能靠导入 Skill 连接本机库。

当前交付以 Ubuntu 24.04 x86_64 原生运行路线为依据。Windows 推荐 WSL2，Windows 原生后端未适配；Docker 仍需网络、进程生命周期、备份与持久挂载改造，不是已验收的一键部署。路线及实际状态见 [HOSTS.md](HOSTS.md) 和 [WINDOWS_DOCKER.md](WINDOWS_DOCKER.md)。依赖必须按操作系统/架构安装，不把旧虚拟环境和浏览器缓存当可迁移程序。

自己的迁移使用代码、完整私有备份、原件及版本清单，在全新目标恢复并核对；不要跨系统复制运行中的数据库文件。同机换宿主只重新接入原服务。新增 schema 使用新 checksum 迁移，旧迁移不改；关闭产品功能保留已执行 002，不用旧代码强行降级。

朋友分享使用 `./ops/crm share` 的净化源码包；不包含业务数据库、附件、聊天/报告、私有配置、令牌、备份、测试结果和运行依赖。朋友建立自己的数据与凭据。GitHub 只同步独立净化源码历史，不直接推送原项目历史；默认保持私有，不因“方便分享”公开仓库或扩大权限。详见 [SHARING.md](SHARING.md)、[MIGRATION.md](MIGRATION.md) 和 [GITHUB_BACKUP.md](GITHUB_BACKUP.md)。

## 安全、许可与成本

reader 查询，writer 普通录入，owner 处理使用者已决定的冲突与纠错；这些角色不是同系统账户之间的安全沙箱。真实资料交给新的模型/第三方、对外发送、付费、公开部署、扩大权限或不可恢复删除，必须另行授权；普通录入不包含这些授权。

宿主模型的数据流与费用由宿主配置和账号决定，本机保存不意味着所有分析都在本地。外部企业查询只发必要条件，不带整份档案；账号、额度、价格、缓存/再分发条件和凭据存储需在接入时核实。研究原始结果、URL 和日志也不得包含认证头、token 或签名参数。

保留本项目与 Twenty、PostgreSQL、Redis 及其他实际依赖的许可证。Twenty 的 AGPL 文本和标记为 Enterprise 的文件条款应分别核对；研究工具组件的开源许可不授予第三方数据任意再分发权。未确认完整许可的外部 Skill 和工具不随默认源码运行时整体复制。
