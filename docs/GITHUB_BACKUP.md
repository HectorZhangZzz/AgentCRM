# GitHub 源码版本与后续更新

GitHub 保存 Agent CRM 的程序、完整业务要求、Skill、部署/使用说明、合成测试和依赖锁。个人数据库、原件、聊天/报告、凭据和完整私有备份不上传；只克隆源码不能恢复客户历史。

当前维护目标是既有私有仓库 [AgentCRM](https://github.com/HectorZhangZzz/AgentCRM)。每次发布都应重新读取实际仓库可见性和分支状态；本文描述流程，**不构成本轮上传已经完成的回执**。

## 准备独立的净化历史

在实际项目根目录执行：

```bash
python3 ops/github_backup.py prepare
```

工具复用 [源码分享](SHARING.md) 的允许目录和排除规则，将当前经过审阅的源码准备到 `.local/github-source/` 独立 Git 仓库。它不复制原项目 `.git`，不改写原历史，不读取 GitHub 令牌，也不连接或上传 GitHub。

快照包含业务要求、实际能力、Skill、实现和安装来源，默认排除 `vendor/twenty/`；上游由接收者按 [THIRD_PARTY.md](THIRD_PARTY.md) 独立获取。个人数据、私有配置、依赖、运行时、构建缓存、备份和 `test/results/` 同样不进入快照。后续增加目录时须检查分享允许清单，而不是把整个工作目录直接加入 Git。

快照是受管理的发布中间产物，不是日常开发目录。管理标记不符、未知文件、快照自身未提交修改或异常目录会阻止覆盖，不能删除保护标记绕过检查。`prepare` 读取的是本轮允许目录的当前工作树，快照说明中的原仓库提交只作追溯，不代替对未提交源码的审阅。

## 优先使用已有 GitHub 连接器

已有连接器能完成仓库读取、Git 对象、提交与分支操作时，优先使用，不因系统 GitHub CLI 未登录而重复要求登录。账号授权、工具能力和目标仓库权限分别核对；不能从其他应用读取凭据补足缺失能力。

只使用净化快照作为上传来源，并按以下步骤完成普通提交：

1. **读取目标。** 确认目标是预期私有仓库、未归档/停用，读取 `main` 当前提交作为 `expectedHead`。已有远端内容先审查，不能覆盖别人提交。
2. **建立完整预期清单。** 以净化快照的路径、文件模式和 Git blob SHA 形成完整目标树；与远端比较，只上传新增或变化的 blob，未变对象复用。删除项必须明确列入变化，不能把增量文件误当完整树。
3. **创建树和提交。** 以完整清单创建 tree，以已核对的 `expectedHead` 为父提交创建 commit。按文件字节和 executable 模式计算预期树，不能忽略文件模式。
4. **再次检查分支。** 更新前回读远端 head，仍须等于 `expectedHead`；工具支持预期旧提交/租约时一并传入。随后仅作普通、非强制更新。head 已变化或更新被拒时重新审查并协调，不强制覆盖。
5. **回读验收。** 目标分支必须指向新提交，提交的完整树 SHA 必须等于本地预期树；必要时逐层读取路径、模式和 blob SHA 核对。响应截断须递归读取，不能把部分结果当全量验证。最后再次确认仓库仍为私有。

仅创建 blob、tree、commit 或显示“准备完成”都不是备份成功。只有分支和完整树核验通过，才记录可分享的仓库地址、提交和净化源码版本。操作失败只保留本地快照与明确状态，不宣布已上传。

## GitHub CLI 后备

连接器能力不足时可使用官方 `gh`，前提是该 CLI 已在目标环境具备正确认证。连接器认证不自动等于系统 Git/CLI 认证；不得将密码或令牌放进聊天、命令示例、源码或远端 URL。

对于一直由 CLI helper 维护、且本地与远端历史一致的快照：

```bash
python3 ops/github_backup.py publish --repository OWNER/AgentCRM
```

将 `OWNER/AgentCRM` 替换为已核对的目标。helper 会验证账号、私有仓库和普通推送后的分支；仅在明确 404 时尝试新建私有仓库。使用当前已有仓库时不另建重复库，不自动改公开，也不强制推送。helper 的离线模拟测试不是实际上传凭证；发布仍须记录远端结果并核对完整树。

**连接器创建的远端提交，可能与本地净化仓库的提交 SHA 和历史不同。** 从连接器切换 CLI 前须 fetch、审查并协调历史，不能直接假定本地提交等于远端提交，更不能用强制推送消除分歧。

## 后续更新与历史边界

在实际项目修改并验证后，重新审阅允许目录、运行 `prepare`，按同一 expected-head 与完整树核验流程同步。源项目可能含旧资料或上游调试记录，不能在根仓库直接配置远端然后推送原 `main`。

当前树排除上游代码，不会自动删除旧远端提交中的历史副本；普通更新也不会改写既有历史。本次整理不进行强制清史、删除旧提交或公开仓库。如需处理既有历史的许可或资料问题，应另行确定保全与处置方案。

没有自动定时推送任务，也不自动邀请朋友或扩大访问权限。分享源码包不等于开放本机数据库；保密范围扩大、改公开或替换远端历史均须另行授权。

## 恢复和接管

从 GitHub 克隆当前源码，按 [INSTALL.md](INSTALL.md) 准备匹配运行时和上游来源，朋友初始化自己的实例。自己的历史资料则另携完整私有备份，按 [MIGRATION.md](MIGRATION.md) 恢复至全新目标并核对。业务方法、需求和已知限制都随源码保存，接管无需依赖维护者的旧聊天。
