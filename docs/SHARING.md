# 分享给朋友与迁移个人资料

给朋友的是 **Agent CRM 的程序、业务要求与使用方法**；朋友建立自己的数据库和凭据。迁移自己的历史客户资料是另一项私有操作，不能混用分享包和完整备份。

## 分享包包括什么

| 包含 | 不包含 |
|---|---|
| 自有领域服务、管理台、MCP/CLI、运维脚本 | 个人数据库、客户附件、聊天、办公报告、备份与导出 |
| [业务要求](REQUIREMENTS.md)、[实际能力](CAPABILITIES.md)、架构/工具契约/使用与安装说明 | `.local/`、私有配置、访问令牌、账号密码及旧 Git 历史 |
| Agent CRM Skill、宿主模板、合成示例与测试源码 | `test/results/`、运行日志、截图和本机测试数据库 |
| 根依赖锁文件、目标运行时清单与上游获取说明 | `vendor/twenty/`、依赖目录、运行时二进制、构建产物和缓存 |

**默认包不重分发 Twenty 源码。** 上游包含不同许可的组件和标记为 Enterprise 的文件，接收方须按 [THIRD_PARTY.md](THIRD_PARTY.md) 的来源和固定版本独立取得，再按 [INSTALL.md](INSTALL.md) 构建；不因为原电脑有副本就推定可以整体转送。第三方权利与版本说明保留在文档中，本包不重新授予第三方代码许可。

当前运维路线仍依赖按安装说明准备 Twenty 和匹配运行时。排除上游代码不表示已经实现无 Twenty 的完整启动模式；本包也不是解压即运行的 Windows 程序或 Docker 镜像。

## 生成与核验

在项目根目录执行：

```bash
./ops/crm share
# 可指定一个尚不存在的 ZIP 路径
./ops/crm share --out /PATH/TO/agent-crm-source.zip
```

默认输出到 `share/`；不读取业务数据库或本机配置，不停止现有服务。输出文件或同名校验文件已存在时拒绝覆盖。

包内 `share-manifest.json` 逐文件记录相对路径、字节数和 SHA256；同目录 `.sha256` 记录整个 ZIP 的哈希。接收方先核对整体哈希，再核对解压文件与清单；不能只根据文件名判断收到正确版本。生成包是本地动作，不代表已经上传或发送。

打包器按允许目录和排除规则选文件，拒绝源码符号链接、保留文件名冲突和已识别的私钥/令牌模式。但这些规则**不能识别任意写进文档、源码或合成示例的客户资料**。发布前仍需检查本轮改动、文件清单、已知业务标记、绝对路径及敏感信息；不要往允许目录临时放客户文件。

GitHub 同样只同步净化快照，不能直接推原项目历史，见 [GITHUB_BACKUP.md](GITHUB_BACKUP.md)。更换为不含上游的当前树，不会抹除既有远端历史中的旧文件；也不会授权改写历史或删除旧提交。

## 朋友首次安装

1. 校验并解压到独立目录，先读 `SHARE_README.md`、README、[REQUIREMENTS.md](REQUIREMENTS.md) 与 [CAPABILITIES.md](CAPABILITIES.md)。后者区分已实现、默认关闭、方案和未实测环境。
2. 按 [INSTALL.md](INSTALL.md) 和 [运行时说明](../deploy/runtime/README.md) 准备目标系统的 Node 24、Python 3、PostgreSQL 16、Redis 7，以及目录布局；源码包不携带安装好的依赖。
3. 按 [THIRD_PARTY.md](THIRD_PARTY.md) 独立取得指定 Twenty 来源/版本并遵守条款，安装锁定依赖、构建需要的组件。不直接复制另一台电脑的 `node_modules` 或虚拟环境。
4. 在自己的空环境首次初始化，生成独立数据库、凭据和工作区。不要导入分享者的私有备份或复用其客户端配置。
5. 用 reader 验证服务与材料覆盖，再按 [HOSTS.md](HOSTS.md) 选择 WorkBuddy 或 DOTS/Codex。在隔离合成实例完成写入、重复、冲突和查询后再录入自己的客户。
6. 产品领域与页面默认关闭，需要按 [PRODUCT_LIBRARY.md](PRODUCT_LIBRARY.md) 显式决定是否开启；不要将分享者以往实例的开关状态当作默认配置。

Windows 推荐 WSL2 路线，但 Windows/WSL 尚未完整实机验收；Docker 仍需适配。具体边界见 [WINDOWS_DOCKER.md](WINDOWS_DOCKER.md)。目标宿主看到工具或接受配置不等于接管完成，必须实际调用。

## 迁移自己的数据

自己的另一台电脑使用 `backup` / `verify` / `restore`，并携带匹配源码、原件和版本清单。完整私有备份包含客户资料与恢复必需的配置/密钥，须私密保管；克隆 GitHub 或拿到本分享包不能恢复客户历史。

恢复只进入全新目标，核对原件哈希、稳定 ID、关系、历史及当前状态，再切换写入。不要在数据库运行时直接复制物理文件目录，不跨系统硬搬二进制依赖。见 [MIGRATION.md](MIGRATION.md)。

同机换宿主保持同一正式库，只重新接入服务和 Skill；不要为多个 Agent 分别维护多份正式资料。源码分享不会自动给朋友开放本机访问或 GitHub 权限，公开发布和访问范围扩大须另行决定。
